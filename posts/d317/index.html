设备包只描述设备本身，保持简单即可。内核源码、内核 config 和内核 tarball 不要放在 device-vivo-y927，后面单独放到 linux-postmarketos-y927。

填设备包 sha512sums

device-vivo-y927 的 checksum 要放在 modules-initfs 建立之后执行，因为 modules-initfs 也属于设备包 source。

建立 linux-postmarketos-y927/APKBUILD 文件（7.0 移植版）

7.0 内核仍然从 ~/y927/linux 本地仓库生成快照 tarball，但 APKBUILD 本身只消费 source 里的 tarball 和 config，不在 prepare() 里访问 $HOME/y927/linux。这样更符合 abuild 的模型，也避免 chroot 里访问宿主目录导致不可复现。

相关内核改动已经整理到 msm8916-mainline/linux PR：

  • PR：https://github.com/msm8916-mainline/linux/pull/448
  • head 分支：zhangzqs/linux-msm8916:y927/7.0
  • base 分支：msm8916-mainline/linux:wip/msm8916/7.0

截至 2026-07-04，这个 PR 仍是 Draft，尚未合并，所以这里仍然以本地 ~/y927/linux 打出的 tarball 为构建来源。这样可以避免 PR 后续 rebase、force-push 或拆分提交时影响本文流程复现。等 PR 合并后，再把 APKBUILD 的 source 改成稳定的上游 commit、tag 或分支会更合适。

注意这里是内核包 linux-postmarketos-y927 的目录，不是前面的设备包 device-vivo-y927。device-vivo-y927 里只放 deviceinfo、设备包 APKBUILD 和 modules-initfs；内核源码包、内核 config 和内核 tarball 放在 linux-postmarketos-y927。

生成安装镜像

第一次刷入前需要先运行 install，让 pmbootstrap 生成 rootfs 和 boot.img。后续如果只改内核，也建议重新执行一次 install，确保导出的 boot 镜像使用刚构建的内核包。

当前验证状态

截至 2026-07-04，本文流程已经在构建环境中验证到以下阶段：

  • pmbootstrap build linux-postmarketos-y927 --force
  • pmbootstrap build device-vivo-y927 --force
  • pmbootstrap install
  • pmbootstrap export

还没有覆盖实机 fastboot 刷入后的启动验证。刷入后需要继续确认显示、触摸、USB NCM SSH、Wi-Fi、音频、电池/充电等功能状态。
